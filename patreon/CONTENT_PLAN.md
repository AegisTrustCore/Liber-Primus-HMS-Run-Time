# Patreon Content Plan

All Patreon content starts as a draft with an audience, evidence boundary, source set, and approval state. Posts are scheduled by capability and evidence readiness rather than unsupported deadline promises.

| Content type | Typical audience | Purpose |
|---|---|---|
| Public orientation | Public | Explain HMS, link GitHub, and state current release status |
| HMS Dispatch | Pilgrim+ | Summarize completed work, current work, and the next validated gate |
| Research queue | Navigator+ | Preview approved candidates and invite bounded prioritization |
| Evidence ledger | Cartographer+ | Provide deeper experiment/control/negative-result organization |
| Frontier briefing | Admiral | Explain experimental systems, review needs, and access boundaries |
| Build release | Eligible tier | State what shipped, version, access, limitations, and next gate |
| Research release | Eligible preview tier, then public | Present claim, method, evidence, controls, limitations, and public-release plan |
| Correction notice | Same or broader audience as original | Preserve the original context and state exactly what changed |

## Post status

```text
DRAFT → INTERNAL REVIEW → APPROVED → SCHEDULED → POSTED → CORRECTED/ARCHIVED
```

No draft is a member entitlement. `POSTED` must be confirmed from Patreon before a manifest status changes.

## Required post sections

1. Audience and access level
2. Material type: software, research, community, or mixed
3. Evidence status where research is discussed
4. What exists now
5. What remains planned or unverified
6. Links to relevant GitHub public evidence
7. Member action or feedback request
8. Correction history
