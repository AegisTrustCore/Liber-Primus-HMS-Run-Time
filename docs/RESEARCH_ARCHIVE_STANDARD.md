# HMS Research Archive Standard

## Fundamental boundary

```text
RAW EXECUTION → STRUCTURED RUN OBJECT → HUMAN-READABLE PRESENTATION
```

Markdown explains HMS research. Canonical `RUN`, `RES`, `CAP`, and `RSET` manifests are HMS research.

## Object meanings

- `RUN-####` records one actual execution: inputs, parameters, pipeline, output, controls, interpretation, limitations, and provenance.
- `RES-####` records a bounded finding supported by one or more Runs.
- `CAP-####` groups a coherent investigation.
- `RSET-####` selects approved objects for distribution without changing their truth status.

Membership level changes access and detail, not truth.

## Minimum public package

Every published Run has at least:

```text
manifest.json
result.json
result.txt
result.html
README.md
provenance/provenance.json
SHA256SUMS
RUN-####.zip
```

Inputs, parameters, pipeline, metrics, structured output, and preserved raw artifacts are included when available. Missing historical information is explicit; it is never reconstructed without evidence.

Every published Result has a canonical manifest, structured evidence and supporting-run links, portable HTML and text views, checksums, and a ZIP.

## Source of truth

`manifest.json` and structured output are authoritative. HTML, text, Markdown, CSV, indexes, checksums, and ZIPs are generated by:

```bash
python scripts/build_research_archive.py
```

The mandatory public validator checks object relationships, source hashes, package checksums, required representations, and offline links.

## Historical integrity

- Preserve historical source identity and source system, including Codex or ChatGPT where applicable.
- Record normalization changes without altering original numeric output.
- Preserve incorrect historical terminology in raw material and add a current HMS note separately.
- Use `NOT_AVAILABLE`, `UNKNOWN`, or partial migration confidence instead of invented metadata.

## Disclosure boundary

Potential unknown plaintext, key material, hidden endpoints, unreleased selectors, candidate solutions, and future puzzle clues remain in private critical hold. Public filenames use neutral permanent IDs and must not leak restricted conclusions.

## Release boundary

Generated files may be staged for review. A staged Run Set is not a tagged GitHub Release asset and must not be described as released until its exact subject passes the human-controlled release gate.

Large artifacts belong in approved release storage with their size, location, and SHA-256 retained in the repository.
